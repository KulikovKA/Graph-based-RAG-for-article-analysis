# Безопасность и ограничения данных

Модель угроз охватывает произвольный ввод, недоверенные документы EPO/OpenAlex, внешнюю обработку минимизированного контекста в Groq, недоверенные ответы модели и доступ к приложению из сети. Проверяются изоляция, ограничение действий агента, защита секретов и точность происхождения цитат.

- Аутентификация: серверная session cookie, Argon2id для локальных паролей или внешний OIDC; auth abstraction позволяет заменить механизм. У всех conversation/run/idea endpoints проверять ownership до cache/index. Межпользовательские тесты обязательны.
- Сеть: только Caddy публикует порт; PostgreSQL, Redis, Neo4j, Qdrant и Airflow ограничены внутренней сетью. Разрешённый исходящий Groq API вызывается сервером. Для внешнего доступа HTTPS, HSTS после корректной настройки, CORS allowlist, CSRF для cookie mutations и rate limit по user/IP.
- Ввод: лимиты размеров и типов, timeouts, quotas jobs, валидированные IDs и enums. Source URL строить из проверенных доменов/ID и позволять только `https`; запрет SSRF, redirects на внутренние адреса и произвольный fetch по URL от клиента.
- Вывод: Markdown рендерить с sanitization, без raw HTML/inline scripts; ссылки с `rel=noopener noreferrer`; evidence IDs сверять с snapshot. Источники и LLM output — данные, не инструкции для backend.
- Секреты: в env/secret store, не в Git/логи/URL; отдельный EPO OAuth token cache; ротация session secret и DB credentials, минимальные DB роли. `.gitignore` защищает только от случайной публикации: `git diff --cached` обязателен перед push.
- Данные: EPO OPS требует соблюдения [условий](https://www.epo.org/en/service-support/ordering/terms-and-conditions/ops-terms-and-conditions) и [fair use](https://www.epo.org/en/service-support/ordering/fair-use); не распространять скачанный корпус как raw dump. У OpenAlex хранить атрибуцию/source URL и перепроверить актуальные условия.
- Логи/backup: не логировать полные идеи, prompts, cookie, токены и raw responses. Шифрование диска/backup, доступ администратора, проверка восстановления и срока хранения. Удаление пользователя удаляет личные conversation/idea/run и очищает связанные caches, сохраняя разрешённые публичные документы.

Перед внешним demo провести проверку TLS, CORS/CSRF, session fixation, horizontal IDOR, prompt injection, SSRF, dependency versions, exposed ports и secret scanning. Запретить external demo при провале любой критичной проверки.

ARCH-002: AUTH-001 реализуется до API-001. До auth gate Compose доступен только на loopback для оператора; LAN разрешается после auth/isolation gate, внешний доступ — после release security gate. Для MVP выбран локальный password login с Argon2id и `auth_sessions`; аккаунты создаёт оператор через CLI, публичной регистрации нет. Login проверяет Origin и rate limit, смена login обновляет session token. Logout/disable отзывает сессию; все mutations требуют CSRF. OIDC остаётся будущим adapter.

Evidence endpoint всегда scoped run + evidence_id; публичный document ID не даёт доступа к чужому run/snapshot. source_run_id принадлежит той же conversation и владельцу. Graph neighbors/cursors и все query-dependent caches проверяются тем же scope. Ответные ссылки строит shell; модель не задаёт source URL. Сырой draft/repair не публикуется в SSE; проверенный fallback не означает доказанную semantic faithfulness. Данные источников не меняют allowlist инструментов/сети.

ADR-011: thinking/analysis channel и raw chain-of-thought отбрасываются на границе inference adapter. Запрет распространяется на GET/SSE/UI, durable storage, messages, logs, tracing, exception body capture и eval artifacts; отдельного debug opt-in для raw reasoning в MVP нет. Логируются только allowlist codes/timings/counts, без rejected JSON values и provider response bodies. Неизвестный/смешанный канал завершается protocol error, не эвристической очисткой и публикацией. Тесты подставляют synthetic sentinel во все provider/error paths и проверяют отсутствие утечки.

PublicAnalysisV1 доступен только владельцу run и содержит проверенные claims/limitations из AnswerV1. Renderer использует строгие шаблоны и проверенную metadata; цитата источника остаётся недоверенным отображаемым текстом, не инструкцией. Partial answer chunks безопасно показываются как текст; Markdown/links активируются только после безопасного разбора целого блока. Session revoke проверяется и для долгого SSE/replay/reset. Cancel/lease fencing блокируют все поздние events, а не только финальный ответ.

## Целевые защиты агента

1. До Planner нормализовать и проверять размеры, типы, scope, лимиты и прямые признаки prompt injection. Извлечённые фрагменты патентов/статей маркировать как внешние данные. Детектор проверяет инструкции, попытки смены роли и вызова инструмента из документа. Подозрительные фрагменты могут быть исключены из модельного контекста с записью причины или показаны как безопасный текст по правилам доступа.
2. Перед каждым tool call проверять allowlist, closed schema аргументов, ownership, графовую версию, списки доступных узлов/источников и остаток budget. SQL и Cypher формируются только параметризованными серверными функциями. Генерация запросов к базам, произвольная сеть или изменение онтологии по указанию модели отсутствуют в наборе инструментов.
3. Перед публикацией проверить schema, ссылки, claims и соответствие цитат evidence snapshot. Смысловую поддержку оценивать отдельно и маркировать неопределённость. Бюджеты регулируют время, число итераций, запросов, токенов и стоимость. После исчерпания остаются безопасный ответ из проверенных материалов либо явная ошибка.
4. Проверять роли и scope для чатов, старых версий графа, источников, курсоров, экспорта, кэша и SSE. Пользовательская идея остаётся приватной. Отдельно тестировать прямую/косвенную injection, неверные tool args, утечки canary, обход scope, поддельную цитату, SSRF и рендеринг. Детерминированные проверки являются основой; специализированный ML guard может улучшить детекцию, а его пропуски и ложные блокировки измеряются.

## Передача идей в Groq

До первого внешнего вызова интерфейс сообщает, что часть технической идеи, выбранного контекста и доказательств передаётся Groq. Пользователь может отказаться или отключить передачу для исследования; при отказе доступен самостоятельный Explorer. Адаптер ограничивает поля и объём, исключает закрытые идентификаторы аккаунта и секреты, применяет правила защиты данных и проверенный список endpoint. Авторизованный контекст и ключи хранятся на сервере. Поведение при хранении данных провайдером зависит от возможностей и настроек аккаунта; их проверяют перед релизом и отражают в уведомлении. Эксплуатационные логи, Airflow и MLflow получают только допустимые версии, IDs, коды и показатели. [Условия обработки Groq](https://console.groq.com/docs/your-data)
