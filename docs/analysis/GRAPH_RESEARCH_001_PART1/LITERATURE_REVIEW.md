# Обзор методов и первоисточников

Дата проверки источников: 2026-10-19. Область: offline graph construction. Retrieval описан только настолько, насколько необходимо отделить его от extraction. Внешние результаты не являются измерениями на Ryzen 7 8845HS, Qwen3.5 4B или frozen corpus проекта. Во всех строках переносимое качество на нашем корпусе — `NOT_MEASURED`.

## 1. Graph-RAG: что действительно строит граф

| Метод и первоисточники | Offline алгоритм | Опубликованные модели / реализация | Grounding, ontology, заимствование и ограничения |

| **LightRAG**, [статья, arXiv:2410.05779](https://arxiv.org/html/2410.05779v1), [код](https://github.com/HKUDS/LightRAG) | Chunk-wise generative entity/relation extraction; name aggregation; descriptions; graph/vector indexing; incremental updates | В v1 эксперименты используют GPT-4o-mini, chunk size 1200, gleaning 1. | **Microsoft GraphRAG**, [arXiv:2404.16130](https://arxiv.org/html/2404.16130v2), [код](https://github.com/microsoft/graphrag) | Entities/relations → summaries → Leiden communities → community reports | В статье GPT-4-family, в extraction appendix GPT-4-turbo; код MIT | Source text units позволяют attribution, но summary не доказательство отдельной связи. Нужен отдельный semantic RE слой; готовая замена technical extractor отсутствует |

Similarity links не считать SAME |

Для 70B указан сервер с четырьмя H100 | Это не доказательство эффективности Qwen4B/CPU. Полезно отделение passage nodes и claim evidence; recognition filter в query path не закрывает offline validation |
| **KG²RAG**, [NAACL 2025 / arXiv:2502.06864](https://aclanthology.org/2025.naacl-long.449/), [метод](https://arxiv.org/html/2502.06864v1), [код](https://github.com/nju-websoft/KG2RAG) | Llama-3 извлекает triples и связывает их с chunks; основная новизна — KG-guided chunk expansion/organization | Статья указывает Llama-3; проверенный HotpotQA extraction script использует `llama3:8b` через Ollama. Это code configuration, exact published digest `UNKNOWN`. GPL-3.0 | Заимствовать triple↔chunk mapping; не переносить lexical filters без проверки: код отбрасывает uppercase `NO`, включая NO2. Expansion не является validator |
| **circlemind FastGraphRAG**, [код](https://github.com/circlemind-ai/fast-graphrag), [LLM client](https://github.com/circlemind-ai/fast-graphrag/blob/main/fast_graphrag/_llm/_llm_openai.py) | LLM extraction, graph maintenance и graph ranking; schema задаёт предметные entities | Прочитанный default client: gpt-4o-mini и text-embedding-3-small; MIT. Это defaults кода, не заявленная модель каждого benchmark | Small local backend требует проверки structured-output поведения. Быстрое graph retrieval не доказывает дешёвое ingestion. Заимствовать separation storage/extraction; точные offsets/qualifiers дополнить |
| **Graphiti**, [код](https://github.com/getzep/graphiti), [edge operations](https://github.com/getzep/graphiti/blob/main/graphiti_core/utils/maintenance/edge_operations.py), [документация](https://help.getzep.com/graphiti/getting-started/welcome) | Episodes → entity/edge extraction → resolution/dedup → temporal facts/invalidation; custom entity types | LLM-based orchestration, provider adapters; Apache-2.0. Сопоставимый patent/Qwen4B benchmark `UNKNOWN` | Полезно версионирование observations и validity. Scientific disagreement при разных температурах не означает временное устаревание факта. Много resolution/validation calls и semantic merge risks; не переносить агентскую memory architecture целиком |

**Вывод исследования:** эти frameworks в основном доказывают полезность структурированного контекста для QA. Ни один из рассмотренных результатов не устанавливает одновременно technical-relation precision, chemical identity correctness, source offsets и CPU cost на целевом корпусе. Их algorithms можно использовать как компоненты, но не как основание выбрать победителя A–E.

Token counts всех frameworks на нашем корпусе `NOT_MEASURED`. CPU-compatible client не означает CPU-feasible end-to-end: HippoRAG2 main 70B/7B setup не удовлетворяет budget; native LightRAG/GraphRAG/Graphiti/FastGraphRAG потребуют local model substitution и повторной проверки. Lazy/NLP construction обходится без generative extraction, но его co-occurrences не являются готовыми semantic claims. KG²RAG code и HippoRAG 8B ablation поддерживают возможность небольшого local extraction, не переносимый quality score.

## 2. Scientific information extraction

| Метод | Проверенная идея и исходник | Что заимствовать | Что ограничивает перенос |
|---|---|---|---|
| **SciIE / SciERC** | Совместные entities, relations и coreference; shared spans. [Luan et al., EMNLP 2018, DOI 10.18653/v1/D18-1360](https://aclanthology.org/D18-1360/) | Multi-sentence evidence, gold entity clusters, separate relation labels | SciERC — scientific abstracts, преимущественно computer science; его labels не равны MATERIAL/ANALYTE/OPERATES_AT |
| **SciBERT** | Domain pretraining с scientific vocabulary. | **DyGIE++** | Contextualized spans, graph propagation для entities/relations/events. | **GLiNER** | Label-conditioned bidirectional span extraction. | **GLiREL** | Relation-label scoring по заданным entity spans. | **MatSciBERT** | Materials-adapted SciBERT; NER/RE и classification tasks. | **DocRED** | Document-level relations с multi-sentence evidence. [ACL 2019, DOI 10.18653/v1/P19-1074](https://aclanthology.org/P19-1074/) | Отдельно оценивать cross-sentence links и negative candidates | Wikipedia/Wikidata ontology; generic checkpoint не готов для operating conditions |

Joint extraction и separate classifiers — альтернативные вычислительные стратегии. PURE показывает, что разделение может быть сильным на стандартных benchmarks; SpERT/DyGIE++ показывают пользу shared representations. Ни один вывод не переносит победу на наш hardware/corpus: нужны одинаковые entity budget, candidate recall и end-to-end scoring.

## 3. Патенты и функциональные отношения

**SAO (Subject–Action–Object)** использует синтаксическую/семантическую структуру действия вместо тематического co-occurrence. Для `sensor detects NH3` это непосредственно полезный кандидат отношения. Dependency parse, verb normalization и controlled predicate mapping могут работать без generative LLM; пропущенный subject, passive voice и длинные claims потребуют разрешения структуры. [Исследование technology knowledge flow, DOI 10.1140/epjds/s13688-025-00598-y](https://link.springer.com/article/10.1140/epjds/s13688-025-00598-y).

**FOP (Function–Object–Property)** отделяет функцию, объект и свойства. Работа FOPNet 2026 строит functional semantic KG и embeddings; здесь доступные сведения подтверждают направление representation, но точный extractor checkpoint, лицензия кода и CPU cost — `UNKNOWN`. Не приписываем статье доказательство superiority на Qwen4B. [Первичная публикация FOPNet](https://www.sciencedirect.com/science/article/pii/S0172219026000025).

Более новый **SAO benchmark 2026** сравнивает LLM/agent extraction на collaborative robotics patents. Это полезный дизайн предметной оценки; большие модели/agent steps не соответствуют нашему resource budget автоматически. Доступная публикация не заменяет independent gold sensor patents и не даёт готовый small-checkpoint contract. [Scientific Reports, DOI 10.1038/s41598-026-49727-1](https://pmc.ncbi.nlm.nih.gov/articles/PMC13279998/).

Для проекта предлагается заимствовать SAO/FOP **как rubric**, а не как готовую универсальную ontology: device/material/process, действие, объект/роль, property/value/unit, condition, polarity, section/claim scope. `Comprising` и `may comprise` различаются по modality; зависимый claim требует ссылки на antecedent, а перечисление alternatives — своего scope. Publication mention не означает experimentally demonstrated relation. До patent holdout качество этих правил `NOT_MEASURED`.

## 5. Синтез для данного исследования

**Рекомендуемые заимствования:** immutable source anchoring из текущего проекта; span-first NER; bounded candidate pairs; closed RE ontology с `NO_RELATION`; context-specific identity decisions; n-ary qualified claims; selective prediction; human-calibrated NLI; replayable versioned evidence.

**Нельзя заимствовать как гарантию качества:** LLM judge win rates из Graph-RAG papers, co-occurrence как факт, cosine как SAME, generic biomedical accuracy как patent accuracy, confidence как калиброванную вероятность, опубликованные GPU speedups как CPU latency.

**Что требует дальнейшего исследования, а не скрытого обещания:** документный coreference для патентных claims; learned numeric entailment; полностью готовая scientific NER+RE голова именно нашей ontology; semantic validation химических aliases; русский technical corpus. Найденные материалы обосновывают кандидатов, но не снимают эти пробелы.
