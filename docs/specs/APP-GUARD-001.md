# APP-GUARD-001 — граница контекста и инструментов

Опоры: [SECURITY](../SECURITY.md), [LLM_CONTRACTS](../LLM_CONTRACTS.md), [INT-GROQ-001](INT-GROQ-001.md). Реализация в отдельном модуле политик и проверяемых портах, без включения отправки приватных данных. Groq сохраняет свой низкоуровневый legacy-совместимый порт. Для будущего агентного маршрута вызов внешнего порта возможен только через защищённую границу. Тестовые smoke-вызовы используют синтетические данные отдельно от обработки чатов.

Серверная политика по умолчанию запрещает передачу. Согласие должно соответствовать owner, conversation, run и версии уведомления. До первого вызова UI сообщает о передаче выбранного контекста и возможности отказа. Контекст строится по закрытому списку полей с ограничением объёма и удалением секретов, технических идентификаторов и неавторизованных данных. Системные инструкции отделяются от сериализованных пользовательских данных. Подозрительные инструкции обрабатываются как недоверенный контекст либо отклоняются. Решение о доступе и вызове принимает сервер.

Инструменты получают строгие DTO с закрытыми полями. Реестр ограничен серверными функциями поиска, соседей, путей и источников. Ownership, версия снимка и принадлежность ссылок проверяются до dispatch. Аргументы с SQL, Cypher или назначением для сетевого запроса отсутствуют в контракте. Принимается только scoped request с общим бюджетом, deadline и cancellation. Ответ, пришедший после отмены, не передаётся следующей стадии. Отсутствие порта или полномочий приводит к безопасному отказу. Источники остаются недоверенными вплоть до проверки evidence.

| ID | Given → When → Then | Проверка |
|---|---|---|
| GUARD-1 | Нет действующего согласия или изменился scope → запрос внешней генерации → безопасный отказ до вызова, согласованный запрос передаёт только разрешённые данные | Canary fixture, fake provider |
| GUARD-2 | Пользовательский текст, документ или ответ содержит инструкции → обработка → инструкция не влияет на системный prompt, scope и набор инструментов | Прямые/косвенные negative fixtures |
| GUARD-3 | Неизвестный инструмент, extra/неверный тип, чужой узел/run, версия, URL или запрос к БД → dispatcher → отказ до порта | Типизация и negative fixtures |
| GUARD-4 | Общий бюджет исчерпан или deadline/cancel наступил → новые вызовы не отправляются, поздние ответы отбрасываются | Fake provider/dispatcher с общей квотой, retry контракт Groq |
| GUARD-5 | Неподтверждённый evidence или повреждённые данные → публикация → безопасный отказ, секреты и canary отсутствуют в ошибках | Negative fixtures, затем I-SEC |

Перед закрытием I-SEC проверяются реальное подключение guarded provider, согласие из сессии, отзыв, версии, негативные сценарии на полном маршруте и настройки Groq. Откат сохраняет запрет отправки и текущий legacy Runtime.

### Согласие для запуска

`GET|POST|DELETE /api/v1/runs/{run_id}/external-consent` используют владельца текущей сессии и принадлежащий ему run с его conversation. POST и DELETE требуют Origin/CSRF. GET и POST возвращают `{notice_version: "groq_context_v1", granted: boolean}`. POST принимает только `{notice_version: "groq_context_v1"}`. Неизвестные поля, неверные типы и неподдерживаемая версия дают 422. GET без записи возвращает `granted:false`. DELETE идемпотентен и возвращает 204. Чужой и неизвестный run дают один 404. Потерянная сессия даёт 401. Подтверждение одного run не переносится на другой. Удаление run/chat удаляет связанные согласия. Версии уведомлений не переиспользуются при изменении описанной обработки.

| ID | Дано → действие → результат | Проверка |
| --- | --- | --- |
| GUARD-6 | Новый запуск → владелец читает, подтверждает, перезапускает API и отзывает согласие → последующие запросы соответственно видят false, true и false | API/OpenAPI, PostgreSQL, повторное создание приложения |
| GUARD-7 | Согласие отозвано или версия/владелец/чат/run изменены → Guard проверяет перед вызовом и после ожидания → новый вызов запрещён, поздний ответ не используется | Fixture authorized synthetic route, real repository и тест гонки |

Тестовый маршрут использует внедряемый серверный порт и фиксированный синтетический контекст. Контекст из API, истории, пользовательского ввода или корпуса не отправляется внешней модели до I-SEC. Проверенная оболочка управляет выбором полей, схемой, инструментами и доступом независимо от обнаружения инструкций. На один синтетический прогон общий deadline/cancel и один `GroqBudget` покрывают генерацию и retries; локальные инструменты имеют общий лимит операций Guard, без повторного учёта одного сетевого запроса.
