# RES-EVAL-001 — общий MLflow

Решение заменяет предположение об отдельном развёртывании в RESEARCH. MAIN владеет одним локальным сервером MLflow 3.10.0, выделенными PostgreSQL и томом проксируемых artifacts. RESEARCH владеет frozen splits, измерениями и manifest. Клиенты используют MLFLOW_TRACKING_URI, доступ ограничен loopback и доверенной Docker-сетью. Учётные данные задаёт оператор. Онлайн-события API/worker остаются в существующем контуре OBS-001.

| Критерий | Вход → действие → проверка |
|---|---|
| EVAL-1 | Пустая БД → разрешённая инициализация → data_expansion, retrieval_quality, llm_as_judge доступны через один URI. После рестарта сохраняются run, параметры, метрики, теги и JSON artifact. |
| EVAL-2 | Завершение DAG или ошибка → безопасное событие для внешнего ID → replay на том же клиентском хранилище привязан к тому же run, статусы FINISHED/FAILED различимы. Отсутствующие измерения имеют признак NOT_AVAILABLE. |
| EVAL-3 | Подтверждённый retrieval report с commit, config и snapshot → запись только измеренных значений, Gold требует разметки. Исторический импорт помечается imported. Обычный запрос не порождает Gold-оценок. |
| EVAL-4 | Синтетические результаты Judge → проверка схемы на fixture. Вызовы модели и массовая оценка вне этой поставки. |
| EVAL-5 | Недоступный сервер → локальный безопасный отчёт или очередь и видимый статус → основной процесс сохраняет свой исход. Неизвестные поля, prompts, документы и произвольные файлы отклоняются до записи. |

Версия схемы 1. Идентификаторы и хеши берутся из доверенных manifests, числовые значения только из агрегированных результатов. Для data_expansion — источник, run/interval, этапы, retries/resume, QA/ACK, счётчики документов/ревизий/связей, длительности и отпечатки. Для retrieval — профиль, EL/BFS, модели, seed/K, split/разметка, recall, all-required, MRR/nDCG, coverage, latency/RSS и отдельные usage/cost. Для Judge — версии модели, генератора, rubric/prompt, dataset/split, измеренные оценки, согласие, токены, стоимость и latency. Новая схема подключается к общему транспорту. Граница интеграции — I-RES/I-OBS.

Хранение на постоянных томах до окончания защиты. Перед обновлением остановить отправителей и tracking server, сохранить pg_dump и согласованную копию artifacts, проверить восстановление пары в изолированной среде. Удаление — отдельное решение владельца. При откате сохранить тома и pending events.
