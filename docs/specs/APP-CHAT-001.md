# APP-CHAT-001 — управление чатами и история исследований

Опоры: [API_CONTRACTS](../API_CONTRACTS.md), [DATA_MODEL](../DATA_MODEL.md), [APP-MEM-001](APP-MEM-001.md). Backend меняет маршруты чатов и вынесенный сервис жизненного цикла. Frontend использует существующие сессию и CSRF. OpenAPI и итоговую интеграцию проверяет оркестратор.

- `PATCH /api/v1/conversations/{id}` принимает закрытый JSON `{title: string | null}` с обязательным полем. Пробельный заголовок недопустим, длина до 160 символов, `null` сбрасывает название. Ответ `200 ConversationV1`.
- `GET /api/v1/conversations/{id}/runs?cursor=…&limit=…` возвращает `{items,next_cursor}`. Элемент имеет `id,status,outcome,created_at,completed_at,idea_version_id,index_generation_id`. Устойчивый порядок по `created_at,id` от новых к старым, курсор только внутри выбранного чата. Документы и citations читаются по исходному run.
- `DELETE /api/v1/conversations/{id}` возвращает `204` после durable удаления, включая принадлежащие чату сообщения и runs. Публичные источники сохраняются. При длительном конфликте блокировок транзакция откатывается и возвращается `503 CHAT_BUSY`. SQL ownership остаётся обязательным до чтения кэша. Очистка namespace Redis выполняется после commit и деградирует при недоступности Redis, а отсутствие durable chat отзывает доступ сразу. Старые ключи ограничены TTL.

| ID | Given → When → Then | Проверка |
|---|---|---|
| CHAT-1 | Два аккаунта → владелец меняет название и читает страницы истории → сохранённые даты, версии и порядок, чужой ID даёт 404 | HTTP с PostgreSQL |
| CHAT-2 | Запрос без сессии или валидного CSRF, либо неправильные поля → мутация → 401/403/422 без изменения данных | HTTP negative |
| CHAT-3 | Чат содержит активный run или старый worker завершает работу → DELETE → потомки исчезают атомарно, прежний lease и поздние writes отвергаются, публичный источник читается | PostgreSQL, queue fencing и API |
| CHAT-4 | Есть Redis cache или Redis недоступен → DELETE → чат, run и приватные данные недоступны сразу, ключи отзываются при рабочем Redis | PostgreSQL и Redis, API/browser |

Публичные GraphV1 и Source DTO сохраняются. Откат приложения убирает новые действия. Удалённые данные восстанавливаются из резервной копии в рамках политики хранения. Общая приёмка использует I-MEM/I-UI.
