# MAIN-INFRA-003 — локальные секреты и административный доступ

Опоры: [развёртывание](../DEPLOYMENT.md), [tracking](../TRACKING.md), [безопасность](../SECURITY.md). Миграция сохраняет версии образов, имена проектов и существующие тома. Учётные данные пользователей приложения остаются хешированными. Данные RESEARCH не используются при миграции.

| ID | Дано → действие → результат | Проверка |
| --- | --- | --- |
| INFRA-1 | MAIN использует файлы и окружение → оператор инвентаризирует имена, приоритет, конфигурацию контейнера и активные учётные записи → значения переносятся в защищённый файл без ротации; при неподтверждённом конфликте перенос соответствующего значения останавливается без перезаписи | Сравнение в памяти, проверка совпадения без вывода; аудит имён в Git и Docker |
| INFRA-2 | Несекретный и защищённый env-файлы заполнены → запускается Compose или локальный Python → потребители видят нужные переменные; конфликт с окружением явно обработан; секреты других служб отсутствуют | Тихая проверка Compose, проверка наборов имён, синтетические тесты приоритета, отсутствие секретов в diff |
| INFRA-3 | Docker Desktop и существующие ресурсы MAIN → PowerShell-скрипт запускает базы, доступ и tracking → Windows подключается к Qdrant, Neo4j, PostgreSQL, Redis Insight, Airflow UI и MLflow UI только через loopback | Сверка томов/сетей/портов, запросы с Windows и безопасные probes, DAG paused и отсутствие новых запусков |
| INFRA-4 | Требуется ротация → оператор планирует отдельно изменения сервиса, файла и потребителей → описаны проверка, точки rollback и обращение с ключами данных без фактической смены | Ревью инструкции и безопасного шаблона |

Секреты передаются через явные списки переменных на сервис. Имеющиеся внешние ключи берутся только из защищённой конфигурации MAIN или подтверждённого окружения. Пустые внешние ключи допустимы. Защищённый env исключается из Git и контекста Docker. Отличия между источниками разрешаются по реальному использованию без вывода значений. Действующий пароль в PostgreSQL/Neo4j и Airflow UI нельзя определить только по переменной контейнера. Проверка должна использовать аутентификацию или оставить значение в текущем источнике до ручного подтверждения.

Топология доступа использует выделенные loopback-прокси к закрытой сети. К опубликованным административным портам привязывается только 127.0.0.1. Redis Insight получает только адрес Redis, пароль вводится оператором. Скрипт сохраняет имена проектов и томов, не запускает inference и автономный ingestion. При запуске Airflow регистрация DAG остаётся paused. Откат убирает прокси и восстанавливает предыдущую конфигурацию доступа без удаления volumes или изменения базы.
