# Схема агрегированных событий tracking, версия 1

Клиент принимает три словаря params, metrics и tags и вызывает `validate(experiment, params, metrics, tags)`. Перечни ниже являются allowlist. Измерения передаются только при наличии. Тег `unavailable_fields` содержит через запятую имена отсутствующих metrics, что означает NOT_AVAILABLE. Одновременная передача числа запрещена. Строковые идентификаторы должны поступать из доверенных конфигураций и manifests. Проверка формата не способна определить смысл произвольного идентификатора, поэтому отправитель не должен помещать в разрешённые поля запросы, документы или секреты. Артефакты проверяются отдельным контрактом транспорта.

Общие params для всех экспериментов — `git_commit` (40 hex), `config_hash`, `corpus_hash`, `graph_fingerprint` (SHA-256), `schema_version` (положительное целое). Общие tags — `imported` (true/false строкой), `unavailable_fields`.

Числа конечны и неотрицательны. Метрики долей находятся в диапазоне 0–1, согласие экспертов допускает диапазон −1–1. Для любых retrieval-метрик обязательны git_commit, config_hash, snapshot_hash, retrieval_profile, split и evaluation_source. Для Gold-метрик дополнительно обязательны verified annotation_status, evaluation_source=gold и corpus_hash. Для качественных метрик Judge обязательны judge_model, generator_model, rubric_version, prompt_version, dataset_hash, split и evaluation_source. Значение schema_version равно 1. Временные поля включают явное смещение ISO 8601. split принимает DEV, CALIBRATION, HOLDOUT или SMOKE. source принимает epo_ops, openalex или mixed. stage принимает complete, failed, skipped, discovery, ingest, projection, qa или publish. error_code ограничен безопасными кодами из schema.py. qa_status и ack_status принимают passed, failed или NOT_AVAILABLE. evaluation_source принимает gold, human, judge, fixture, operational или NOT_AVAILABLE. annotation_status принимает verified, unverified, none или NOT_AVAILABLE.

Для исторического snapshot replay укажите measurement_scope=snapshot_replay. Для эксплуатационного smoke Groq разрешены split=SMOKE, evaluation_source=operational, measurement_scope=groq_smoke, completion_attempts, usage_reported_attempts и estimated_groq_cost_usd. Тарифная оценка охватывает только ответы с известным usage. При отсутствии биллинга groq_cost_usd входит в unavailable_fields.
