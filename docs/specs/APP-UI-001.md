# APP-UI-001 — Explorer и помощник

Опоры: [окончательный план](../FINAL_PROJECT_PLAN.md), [API_CONTRACTS](../API_CONTRACTS.md), [APP-GRAPH-001](APP-GRAPH-001.md), ADR-011/016. Граница изменений — только `frontend/`. Используются существующие chat/Run/Source/SSE DTO и согласованный аддитивный Explorer HTTP контракт. Для самостоятельного Explorer используются Playwright fixtures. Сообщение помощника пока сохраняет действующий `MessageInput`; выбранный context ref подготовлен в UI, передача проверяется после подключения сервера.

Desktop имеет список чатов и выбор режима слева, активный чат/документ в центре и граф справа. На мобильном переключение панелей сохраняет выбранный объект версии. Цитаты и документы открываются по pinned scope, фактический и семантический типы имеют различимые обозначения, граф работает с клавиатурой и масштабированием. Уведомления об истёкшей сессии, недоступности графа и пустой выдаче оставляют доступный путь продолжения. При logout или смене пользователя состояние приватного графа и чата очищается.

| ID | Given → When → Then | Проверка |
| --- | --- | --- |
| UI-1 | Сессия и список чатов → переключение Explorer/Assistant → виден правильный режим и сохранённый чат, действующие сценарии SSE работают | Playwright mobile/desktop и unit SSE |
| UI-2 | В API есть сущности/документы → поиск и открытие исходной/соседней ревизии → в центре читаемый документ/evidence, на графе сохранена выбранная вершина | Mock Playwright для поиска/пустой выдачи и навигации |
| UI-3 | Видна вершина и mixed edges → выбор, раскрытие соседей, pan/zoom либо mobile-переключение → выбор сохраняется, типы различимы, нет overflow | Playwright desktop/mobile |
| UI-4 | Выбрана вершина с ref, затем сменилось представление → контекст подготовлен для дальнейшего использования → текущий POST остаётся совместим, устаревший ref и logout очищают private state | Playwright fixture и проверка payload |
| UI-5 | 404/409/503 или поздний ответ после смены scope → состояние не перезаписывается чужими/устаревшими данными → отображается доступный статус | Playwright negative/mock |
| UI-6 | Сохранены результаты поиска и выбран узел → пользователь меняет ширину панелей, фильтр или строит путь к доступному узлу → сохранены scope, выделение и доступ к документам | Desktop/mobile Playwright fixture |
| UI-7 | Сессия и completed run → скачивание HTML/PDF из чата или истории → файл при 200, сообщение об ошибке при отказе | Playwright на API и временном PostgreSQL с синтетическим worker |
| UI-8 | Выбран принадлежащий пользователю run → интерфейс показывает уведомление и состояние согласия, отправляет явное подтверждение или отзыв с CSRF → состояние соответствует серверу, смена чата/запуска очищает устаревший результат | Desktop/mobile Playwright, ошибки и поздний ответ в fixture, реальный API для согласия при готовом Guard |

UI согласия использует [APP-GUARD-001](APP-GUARD-001.md). Оно не переносится при выборе другого исследования. Действующие запросы анализа, Explorer, история и экспорт остаются доступны в рамках их прежних контрактов. Контрол согласия сообщает текущее состояние тестового контура до включения рабочего маршрута.

Файлы — `src/App.tsx`, `src/features/graph/`, `src/features/sources/`, `src/api/`, стили и тесты. Откат переключателя оставляет исходный chat/run view. Изменяемые/разворачиваемые панели, фильтры, пути и отправка context ref в приложение оцениваются вместе с реальным backend, авторизацией и экспортом на I-UI/G-TEST. Typecheck, lint и Playwright выполняются отдельно от live интеграции.
